## 1. 무엇을 만드나

코스(= 한 강사 · 한 과목, `product-direction.md` §3.5)의 **모든 활성 강의를 완주**한
학생이 응시하는 **수료 시험**. 학습 루프의 마지막 조각이다:

```
배움(강의 — 시청 검증) → 연습(문제은행 — 완주 잠금) → 증명(수료 시험 — mastery)
```

- **시험이 없는 코스도 허용**(수료 시험은 코스별 선택 사항). 활성 시험 문항이
  0개면 학생 화면에 시험 카드 자체가 보이지 않는다 — 그 코스의 "완주"는 지금처럼
  강의를 다 본 것으로 끝난다.
- 수료하면 수료 기록(`course_completions`)이 남고 학생 화면에 수료 배지가 뜬다.
  수료증 PDF·대시보드 지표는 2단계.

## 2. 법적 전제 — 기출은 "비영리 교육용" (★운영 원칙)

- 평가원(수능·모의평가) 기출 등은 **출처를 표시**하고 **비영리 교육 목적**으로
  이용한다는 전제다. 그래서 설계에 두 가지가 강제된다:
  1. 기출 문항(`origin=past_exam`)은 `source`(출처 문구)가 **필수**(없으면 400).
     화면(문항 카드·결과지)에 항상 노출한다.
     예: `출처: 2024학년도 대학수학능력시험 수학 15번`.
  2. **스크래핑·대량 수집을 하지 않는다** — 강사가 쓸 문항을 직접 입력·편집한다.
- **★유료화(영리 전환) 시 이 전제가 깨진다.** 그때는 기출 라이선스(평가원 이용
  허락 등)를 확보하거나 `origin=past_exam` 문항을 내려야 한다. 이 리스크를 알고
  가는 결정이다(2026-07-18). 내신 기출은 학교·교사 저작권이라 비영리라도 더
  조심스럽다 — 1차 대상은 공개된 국가시험·검정류 기출을 권장.

## 3. 완전학습(mastery) 규칙

- **풀** = 그 코스의 활성(active) 시험 문항 전체(예: 20문항).
- **회차(sitting)**: 한 번에 최대 `EXAM_SITTING_SIZE = 10`문항. 출제 대상은
  "아직 정복하지 못한 문항"(정답 이력이 없는 문항)이 우선 — 안 푼 것 → 틀린 것
  순서(문제은행 `bank_mode`와 같은 철학).
- 제출하면 회차 전체를 서버가 채점 → **결과지**(문항별 정오·해설·출처) + 진행
  상황(정복 X/Y).
- **수료 = 풀의 모든 활성 문항에 누적 정답.** 한 번에 만점일 필요가 없다 — 틀린
  문항은 다음 회차에서 다시 풀어 정복하면 된다(Khan Academy식 완전학습).
  "다 맞춰야 완료"라는 목표의식은 유지하고, 만점 1회 강제의 부작용(좌절·답 암기)만
  제거한 형태다.
- **완벽 통과(perfect) — 2026-07-19 정책 재설계.** ~~수료 시점 오답 기록 0~~ →
  **"현재 활성 전 문항을 한 회차에 모두 맞힌 적이 있는가."** 왜 바꿨나: 옛 규칙은
  회차 어디서든 한 문항만 틀리면 영구 박탈이라 완전학습 철학("틀려도 괜찮아, 될
  때까지")과 정면충돌했고, 강사가 나중에 삭제한 문항의 오답도 완벽 통과를 막는
  불공정이 있었다(오답 이력에 active 필터 없음). 재설계로:
  1. 작은 코스(첫 회차=전 문항)는 첫 판 무결점이 곧 완벽 통과 — 종전과 동일하게 자연 획득.
  2. 여러 회차로 조금씩 정복해 수료하면 완벽 통과 아님(한 회차 무결점이 아니므로).
  3. **완벽 도전(재도전 경로)**: 수료 후에도 `session?perfect=true`로 전 문항을 한
     회차에(10 상한 없음) 다시 받아, 한 번에 다 맞히면 완벽 통과로 **승급**한다.
     한 문제라도 틀리면 승급 안 되지만 몇 번이든 다시 도전 가능(영구 박탈 없음).
  이 정의는 오답 '이력'을 아예 보지 않으므로(perfect ← 한 회차 결과), 삭제 문항
  오답이 완벽 통과를 막던 불공정도 구조적으로 사라진다. 완벽 도전은 **수료 학생 전용**
  (미수료 학생의 perfect 파라미터는 무시 — 회차 종류가 학생 상태로 유일하게 갈려
  커버리지 혼동이 없다). 상태 API에 `can_perfect_challenge`(수료·미완벽·응시가능).
- 무응답("잘 모르겠어요")은 **오답으로 채점**(문제은행과 동일 원칙 — 운 좋은 정답
  없음. 틀린 것으로 남아 다음 회차에 다시 나온다).

## 4. 데이터 모델 (신규 4테이블, 마이그레이션 `course_exam_01`)

모든 참조는 **FK 제약 없는 소프트 참조 + 인덱스**(선례: `Course.instructor_id`,
`Lecture.course_id` — 라이브 덤프로 재생성한 로컬 DB collation 불일치로 FK 생성이
실패한다. 무결성은 엔드포인트 검증이 담당).

### `course_exam_questions` — 시험 문항

| 필드 | 설명 |
|---|---|
| id (UUID PK) | |
| course_id (idx) | 소속 코스. 과목은 코스에 고정돼 있어 별도 subject 불필요 |
| prompt / options(JSON) / answer_indexes(JSON) / explain | **강의 문항과 같은 인덱스 기반 형식**(다답 지원) — 채점·검증 로직 재사용 |
| origin | `manual`(자작) \| `past_exam`(기출) \| `lecture`(강의 문항 복사) \| `llm`(AI 생성, 2단계) |
| source | 출처 문구 — **origin=past_exam이면 필수(400)**, 화면 상시 노출(§2) |
| origin_lecture_question_id | origin=lecture일 때 원본 추적(중복 복사 방지) |
| order_no / status(`draft`\|`active`) / created_by | 검수 흐름은 강의 문항과 동일(draft → 검수 → active) |

### `course_exam_sittings` — 응시 회차

| 필드 | 설명 |
|---|---|
| id / course_id / student_id (idx) | |
| questions (JSON) | 출제 구성 `[{question_id, order:[2,0,3,1]}]` — **보기 셔플 순열을 서버에 보관**. 학생은 "표시 순서 기준 선택"을 제출하고 서버가 원본 인덱스로 복원해 채점(답 위치 암기·위조 차단) |
| submitted_at / total / correct | 제출 전 null. **제출된 회차 재제출은 409**(재채점 방지) |

- 학생·코스당 **미제출 회차는 1개** — 발급을 다시 요청하면 기존 미제출 회차를
  그대로 돌려준다(새로고침으로 문항 조합을 다시 굴리는 파밍 차단).

### `course_exam_attempts` — 문항 응답 기록

| 필드 | 설명 |
|---|---|
| id / student_id / course_id / question_id (idx) / sitting_id | |
| result(`correct`\|`incorrect`) / answer(JSON) / solve_time_ms | |

- **정복(mastered) 집합은 이 테이블에서 파생한다**: 정답 result가 1건이라도 있는
  question_id 집합. 별도 상태 테이블을 두지 않는다 — 상태·기록 이중화는 동기화
  버그의 원천이다(문제은행이 LearningAttempt에서 분류를 파생하는 것과 동형).

### `course_completions` — 수료 기록

| 필드 | 설명 |
|---|---|
| id / student_id / course_id (**UNIQUE 쌍**) | |
| passed_at / question_count / sittings_count / perfect | 수료 시점 스냅샷 |

- **수료 후 강사가 문항을 추가해도 수료는 유지된다**(passed_at 고정). 재잠금은
  학습자 신뢰를 깨므로 하지 않는다(상용 인강 표준). 문항 수는 수료 시점 값을
  스냅샷으로 남긴다.

## 5. 흐름과 API

### 강사(운영 콘솔)

| API | 동작 |
|---|---|
| GET/POST/PUT/DELETE `/ops/courses/{cid}/exam-questions` | 문항 CRUD — 코스 소유 스코프는 기존 `_get_ops_course` 재사용(남의 코스 404). past_exam인데 source 없으면 400 |
| (1.5단계) POST `/ops/lectures/{lid}/questions/{qid}/to-exam` | 자기검증 '은행 적합' 판정 문항을 코스 시험으로 복사(to-bank와 동형 — 강의가 코스 미소속이면 400) |

- 콘솔 UI: 코스 관리 모달에 "시험 문항" 버튼 → 문항 목록/편집(강의 문항 모달의
  단순화판 — 출제 시점·되감기 없음, 대신 origin·source 필드).
- 활성 문항 0개면 "수료 시험 없음" 안내(강의의 '검증 없음' 경고와 동형).

### 학생

| API | 동작 |
|---|---|
| GET `/courses/{cid}/exam` | 상태: available(전 강의 완주?) · 풀/정복 수 · passed/perfect |
| POST `/courses/{cid}/exam/session` | 회차 발급(정답 미포함·보기 셔플). **미완주면 403**. 수료 후엔 passed 상태 반환 |
| POST `/courses/{cid}/exam/submit` | 회차 채점 → 결과지 + 진행 + (전 문항 정복 시) 수료 |

- **응시 자격 게이트**: `bank_mode.completed_lecture_ids(db, sid)`가 코스의 활성
  강의 id 집합을 포함하는가 — 문제은행 잠금과 같은 정본(완주 =
  `LectureWatchProgress.status == "done"`).
- 학생 UI: 코스 그룹 말미에 시험 카드. 상태 흐름:
  `잠김("강의 3/5 완주 시 열려요") → 응시 가능 → 진행("수료까지 4문항") → 수료 배지(+완벽 통과)`.
  응시 화면은 자체 UI(캡차 위젯 비사용 — §6 참고).

## 6. 정답 유출·위조 방어 (문제은행과 같은 독트린)

- 발급 응답에 정답·해설 없음. 채점은 서버만.
- 보기 셔플 순열을 서버(sitting.questions)에 보관 — 클라이언트가 제출하는 것은
  "표시 순서 기준 선택"이고 서버가 원본으로 복원해 채점.
- 제출된 회차 재제출 409. 미제출 회차 재사용으로 새로고침 파밍 차단.
- **이 시험은 부정 방지 장치가 아니라 학습 완성 장치다.** mastery는 반복하면 결국
  답을 알게 되는 구조가 맞다(학습이 목적). 부정행위 신호는 행동 데이터가 담당하며
  시험 화면의 행동 수집 연동은 2단계다(그래서 1단계는 위젯 없이 자체 UI —
  solve_time_ms만 기록).

## 7. 기존 지표와의 관계 (결정 사항)

- **시험 응답은 문제은행 정답률(`StudentProgress.accuracy`)·오늘의퀴즈·코인에
  반영하지 않는다.** 재시험 루프라 정답률을 오염시킨다(같은 문항을 정복할 때까지
  반복 = 정답률이 시험 응시 방식에 좌우됨). `LearningAttempt`를 쓰지 않고
  `course_exam_attempts`만 쓴다.
- ~~오답노트에는 넣는다~~ → **(개정 2026-07-19) 오답노트 시스템 자체가 제거 결정됨**
  (`question-bank-scale-design.md` 결정 ④ — SRS가 같은 일을 해 이중 장부). 시험
  오답의 복기는 시험 자체 mastery 루프(틀린 문항 재출제)와 결과지(문항별 정오·해설)가
  담당한다. `_record_wrong` 연동은 구현하지 않는다.
